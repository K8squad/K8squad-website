# Cardinality budget — the enforced metric-label allowlist (obs-plan §5.6)
#
# THIS FILE IS THE MACHINE MIRROR OF obs-plan §5.6. It is the single source of
# truth the cardinality-lint (Story 13.6 / ISI-2238) reads. Edit §5.6 and this
# file together — a drift between them is itself a review finding.
#
# Format: one token per line. Blank lines and `#` comments ignored.
#   ALLOW <key>        a bounded-enum label domain that MAY appear as a metric label
#   DENY  <key> <code> <reason...>   an explicitly-forbidden key (better error than
#                                    a bare "unknown label"); <code> is OBS-9 (PII /
#                                    per-actor id) or OBS-11 (privacy / fingerprint)
#
# Anything a metric emits that is neither ALLOWed nor a bare enum in ALLOW fails
# the build as "out-of-allowlist". A DENY match fails with its specific code.
# Namespace note: the lint strips a leading `ksquad.` before matching, and also
# tests the final dotted segment, so `ksquad.runtime` -> `runtime` (ALLOW) and
# `ksquad.user.id` -> `user.id` (DENY). Keys carry no cluster/tenant values.
